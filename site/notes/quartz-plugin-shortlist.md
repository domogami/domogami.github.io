# Quartz plugin shortlist

Research: September 24, 2026. Compared public plugin documentation/manifests with this preview checkout's installed packages and YAML configuration. No plugins installed, upgraded, enabled, or connected to a vault or publishing destination. This is a suitability review, not a compatibility test or security audit.

## Recommended order

1. Recent Notes: a small “Recently tended” list using an existing dependency.
2. Bases: a separate local bookshelf or topic-index experiment.
3. Excalidraw: one deliberately public drawing to evaluate the Obsidian-to-garden workflow.
4. Independently evaluate Quartz Syncer's publication center with a disposable test vault/repository before building a custom publishing UI.

## Quartz Syncer: evaluate before writing a publishing plugin

**Follow-up:** [Pinned 2.0.18 source evaluation and isolated tests](./publishing-evaluation/README.md) found blockers for our exact-file review requirement. Do not connect the unmodified plugin to the real vault on the basis of this shortlist. The original discovery notes below are retained as context.

[Quartz Syncer](https://github.com/saberzero1/quartz-syncer) is an Obsidian plugin rather than a site-rendering plugin. Its [usage guide](https://saberzero1.github.io/quartz-syncer-docs/usage-guide) documents a command/ribbon publication center, opt-in publication flags, new/changed/published file lists, selectable changes, split/unified diffs, and a final publish button. This is close to the requested manual review UI.

Its [folder guide](https://saberzero1.github.io/quartz-syncer-docs/guides/configuring-a-specific-folder-for-quartz-content) describes limiting the content root and rewriting links. Its README also advertises background preparation, automatic publishing, and direct publishing commands. Our evaluation should keep automatic publishing disabled and use the reviewed manual flow.

What remains unverified: whether the final confirmation covers every attachment and transformed/transcluded byte; whether private-folder exclusions override all other inclusion routes; whether content changing after review invalidates approval; and whether it can run the required local Quartz build/preview before any remote commit. The documented workflow sends selected content to the repository; it is not evidence that it reproduces our exact export → local build → review → commit/push pipeline. No conclusion about privacy suitability should be drawn from a `publish: true` flag alone.

A disposable test vault/repository should include a public note, a private linked note, a private transclusion, an attachment, a query result, a deletion, and a change made after the review opens. Check the exact exported files and repository diff before considering the real vault.

[Explicit Publish](https://github.com/quartz-community/explicit-publish) is also installed locally at 0.1.0 but not enabled. Its implementation filters pages by a frontmatter publication flag. It could add a build-time guard, but it does not prevent private source files from being copied or committed, review attachments, or provide per-publish confirmation. The export/review boundary is still required. Unlisted pages likewise remain published; they are not private storage.

## Compatibility and maintenance evidence

The six candidate Quartz repositories checked through GitHub's public API—recent-notes, bases-page, obsidian-plugin-excalidraw, canvas-page, citations, and stacked-pages—were non-archived, reported pushes on September 14, 2026, and declared Quartz `>=5.0.0` in their current manifests. Their repository-head package versions were 1.0.0. These are repository/manifests observations, not assertions about npm releases or successful integration into this checkout.

Quartz Syncer's repository reported a September 22, 2026 push and package version 2.0.18. The current README requires Obsidian 1.13.0+ and Quartz 5 for full functionality; some documentation still mentions older requirements. Verify the chosen released artifact when evaluating it.

This checkout uses npm-sourced packages, several at earlier versions than repository head. Avoid copying a latest-README configuration or upgrading every plugin at once. First try an already-installed compatible version with public fixtures; if an update is needed, pin and test it separately. Recent repository activity and broad version declarations do not guarantee compatibility with a future Quartz major version.

There is an [open report about Recent Notes clipping in short sidebars](https://github.com/jackyzha0/quartz/issues/2463). It supports starting with a short main-column list and testing small viewport heights. This report does not establish whether the latest repository build fixes the issue.

Keep theme overrides and any adapters in `site/notebook`; avoid modifying community plugin source. Future checks should cover all themes, mobile layouts, reduced motion, normal and anchor navigation, and the exact approved publication manifest. Site plugins must only consume the reviewed public export.
